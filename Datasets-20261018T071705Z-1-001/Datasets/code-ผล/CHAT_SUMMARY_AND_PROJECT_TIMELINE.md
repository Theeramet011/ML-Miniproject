3. **การรวมยอดเบิ้ล (Double Counting):** มีแถวสรุปยอดระดับประเทศ (`CC-CODE == 0` หรือ `ทั่วประเทศ`) และแถวสรุปยอดจังหวัดปะปนอยู่ในตารางย่อย หากนำไปหาผลรวมหรือค่าเฉลี่ยทันที ตัวเลขจะเบิ้ลเป็น 2 เท่า

## 2. กระบวนการทำ Data Preprocessing (สถิติประชากร)

ได้พัฒนาสคริปต์อัตโนมัติ: [`data_preprocessing.py`](file:///c:/Users/AI/Documents/MiniProject%20Machine%20learning/data_preprocessing.py) เพื่อคลีนข้อมูลทั้ง 3 ระดับ โดยมีขั้นตอนดังนี้:
1. ระบุการอ่านไฟล์ด้วย `sep='|'` และลบคอลัมน์ว่างด้านหลังทิ้ง
2. แปลงข้อความตัวเลขที่มีเครื่องหมาย `,` ให้เป็นตัวเลขจำนวนเต็ม (`int64`)

4. แตกคอลัมน์เวลา `YYMM` ออกเป็น `YEAR_BE` (ปี พ.ศ.), `YEAR_CE` (ปี ค.ศ.), และ `MONTH`
5. แยกแถวยอดรวมประเทศ (`CC-CODE == 0`) ออกไปเก็บในไฟล์สรุปต่างหาก
6. สร้างฟีเจอร์เบื้องต้น: `SEX_RATIO` (ชาย/หญิง), `AVG_HOUSEHOLD_SIZE` (คน/บ้าน), `FEMALE_PCT` (% หญิง)
7. บันทึกผลลัพธ์เป็น UTF-8 with BOM (`utf-8-sig`) ไว้ในโฟลเดอร์ [`cleaned_data`](file:///c:/Users/AI/Documents/MiniProject%20Machine%20learning/cleaned_data):

## 3. การจัดการกับข้อมูลสูญหายและค่าว่าง (Handling Missing Values)

**หลักการสำคัญ:** ไม่มีการสร้างหรือเติมข้อมูลจำลองมั่วๆ (No Synthetic Imputation) แต่ใช้วิธีการคัดกรองตามหลัก Data Science ดังนี้:
1. **คอลัมน์ที่ว่างเปล่า 100%:** 
   * คอลัมน์ท้ายสุด `Unnamed: 13` ที่เกิดจาก Trailing Pipe ถูก **Drop ทิ้ง**
   * คอลัมน์ระดับหมู่บ้าน (`CCAATTMM-*`) ที่ไม่มีการบันทึกข้อมูล (มีค่าเป็น 0 และว่างเปล่าทุกแถว) ถูก **Drop ทิ้ง**
   * คอลัมน์ระดับล่างในไฟล์ระดับบน (เช่น อำเภอ/ตำบลในไฟล์จังหวัด) ถูก **Drop ทิ้ง** เพื่อไม่ให้มีคอลัมน์ว่างค้าง
2. **แถวที่มีตัวเลขเป็น 0:**
   * ในระดับอำเภอมี 11 แถว และตำบลมี 614 แถว ที่ประชากรเป็น 0 (มักเป็นสำนักทะเบียนท้องถิ่น/เทศบาลที่เพิ่งก่อตั้งใหม่) **ยังคงเก็บแถวนั้นไว้ตามจริง**
   * ในการคำนวณอัตราส่วน ได้ใส่ `np.nan` ป้องกันการหารด้วยศูนย์ (Division by Zero) ไว้

## 6. กระบวนการสร้างโมเดล K-Means ทั้ง 6 ขั้นตอน (End-to-End Pipeline)

ได้พัฒนาสคริปต์อัตโนมัติ: [`run_kmeans_pipeline.py`](file:///c:/Users/AI/Documents/MiniProject%20Machine%20learning/run_kmeans_pipeline.py) ซึ่งรันครบทั้ง 6 ขั้นตอน:

```
[Step 1: Data Merging]
รวม cleaned_province.csv (ปี 2563) + electricity_consumption_2563.xlsx
ด้วย Primary Key: CC-CODE == รหัสจังหวัด -> แมตช์ครบ 77 จังหวัด (100%)

[Step 2: Feature Engineering]
คำนวณอัตราส่วนเชิงพฤติกรรม 4 ตัวแปรหลัก:
1. ELEC_PER_CAPITA    : อัตราการใช้ไฟบ้านต่อคน (kWh/คน)
2. ELEC_PER_HOUSE     : อัตราการใช้ไฟบ้านต่อหลังคาเรือน (kWh/หลัง)
3. IND_ELEC_RATIO     : สัดส่วนการใช้ไฟโรงงานอุตสาหกรรมขนาดใหญ่ (%)
4. AVG_HOUSEHOLD_SIZE : ขนาดครัวเรือนเฉลี่ย (คน/หลังคาเรือน)

[Step 3: Feature Scaling]
ใช้ StandardScaler ปรับทุกตัวแปรให้อยู่ในสเกล Mean = 0, Std = 1
เพื่อให้การคำนวณระยะห่าง Euclidean Distance เท่าเทียมกันทุกมิติ

[Step 4: Finding Optimal K]
ทดสอบ K = 2 ถึง 8 ด้วย Elbow Method และ Silhouette Score
ได้ข้อสรุปว่า K = 3 เป็นจุดที่เหมาะสมที่สุด (Silhouette = 0.3518)

[Step 5: Train K-Means Model]
ฝึกสอนโมเดล KMeans(n_clusters=3, random_state=42)
และกำหนด Cluster Label ให้กับทุกจังหวัด

[Step 6: Visualization & Profiling]
1. ใช้ PCA 2D ลดมิติ (อธิบายความแปรปรวนได้สูงถึง 90.02%) พล็อตกราฟแยกสี 3 กลุ่ม
2. พล็อตกราฟ Scatter Plot ค่าไฟต่อบ้าน vs สัดส่วนไฟอุตสาหกรรม
3. สรุปตาราง Cluster Profile ค่าเฉลี่ยของแต่ละกลุ่ม
```

## 8. ทำไมต้องทำ Silhouette Score ร่วมกับ Elbow Method?

1. **ยืนยันด้วยวิทยาศาสตร์ ไม่ใช่ความรู้สึก:** Elbow Method มักมีจุดหักมุมที่โค้งมน การใช้ **Silhouette Score** ($s = \frac{b - a}{\max(a, b)}$) จะช่วยคำนวณวัดระยะห่างระหว่างคลัสเตอร์และความแน่นหนาภายในกลุ่มอย่างเป็นตัวเลขเชิงประจักษ์
2. **ผลการทดสอบของชุดข้อมูลเรา:**
   * $K=2$: Silhouette = 0.449 (สูง แต่หยาบเกินไป แบ่งได้แค่ กทม. vs ต่างจังหวัดทั้งหมด)
   * **$K=3$:** **Silhouette = 0.352 (จุดลงตัวที่สุด)** คะแนนสูงและเป็นจุดหักมุมของ Elbow พอดี ทำให้ได้ 3 กลุ่มที่มีมิติทางเศรษฐกิจสมบูรณ์
   * $K \ge 4$: คะแนนเริ่มตกลงอย่างต่อเนื่อง แปลว่าการแบ่งกลุ่มย่อยเกินไปทำให้ข้อมูลเริ่มทับซ้อนกัน
